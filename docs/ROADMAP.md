# Rule Engine 产品路线图

> **怎么用这一页**：一屏看清各产品主线"现在做到哪了 / 下一步 / 未来"。这里只做高层概览，不写实现细节——
> 已落地项的细节见 [`00-decisions.md`](./00-decisions.md) 同名决策；未做项的设计方向与触发条件见 [`08-evolution.md`](./08-evolution.md) §二各锚点。
>
> **时间档用"现在 / 下一步 / 未来"，不写日期**：诚实、免维护时间承诺。能力从"下一步"做完就挪到"现在"。

|---|---|---|---|
| **规则与决策** | 布尔 / 评分卡 / 决策树 / 决策表 / 脚本规则 / 决策图编排六种形态 + XOR 节点；版本化、灰度（含 A/B 实验互斥）、草稿即冻结快照、发布与回滚；纯决策输出，多规则按策略合成（优先级 / 全命中 / 首命中）；规则模板：平台级模板子系统（身份/快照分离版本化、SlotRefResolver SPI、实例化流水线、跨租户可见性） | — | 规则间编排（命中后顺序依赖交流程引擎，接 Flowable）
| **数据接入 / 取数** | 属性 / SQL 聚合 / 外部 HTTP 三类取数 + 声明式可复用连接器；指标版本化 + 影响面查询；注解式取数；实时流式通道（rt-stream / rt-bridge） | 流式特征作为通用取数档（STREAM）完善 | 物化特征层（预计算 + CDC 刷新）、AI 模型打分接入 |
| **可解释与可观测** | 全节点 trace + 单点失败降级；历史评估忠实重放；敏感数据读时脱敏；系统监控指标 + 告警；基础设施可观测（OTLP + LGTM）；决策效果度量（`decision_outcome` 回灌 + B32 聚合骨架就绪） | 按规则 precision/recall 真实数据聚合（待业务侧回灌真实标签） | what-if 批量回放 / 新规则上线前陪跑 |
| **接入与触发** | HTTP API（同步 / 异步双模）；嵌入式 SDK（注解式规则 + HTTP 轮询保鲜）；定时调度触发（单机 + XXL 多实例）；规则导出 / 导入 Bundle | — | 嵌入式 SDK 准实时变更推送（MQ / Nacos watcher，秒内一致）、评估链路异步化 |
| **规则治理** | 全配置审计；规则集静态分析 / 冲突检测（7 类检查）；规则↔指标↔决策双向血缘 + 变更影响预检；规则列表 / 审计查询 API；决策效果闭环（`decision_outcome` 表 + 同步回灌 API + `OUTCOME_INGESTION` 定时拉标签 + JSON_TABLE 聚合 + 前端报表） | 真实标签回灌后的 precision/recall 持续监控 | 规则模板市场、合规增强（字段级加密 / 审计防篡改 / 右遗忘） |
| **性能与规模** | 评估期预编译（可切换，默认关）；批量预拉取数；亚微秒级求值；调度多实例；规则评估并行求值（场景级 opt-in，默认 SEQUENTIAL） | 编译版生产灰度开启 | 跨规则公共子表达式共享、评估观测数据异步化、trace 冷热分级 |

## 维护方式

- 这一页是**索引视图**，不是真相源。某项做完后：把它从"下一步"挪到"现在"，并去 `00-decisions.md` 追决策、`08-evolution.md` 翻对应锚点状态。
- "下一步"里的候选项按迁移成本 + 依赖排过序，从里面挑就是下一阶段要做的；要不要做、先做哪个由产品判断决定。
