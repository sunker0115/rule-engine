# D11 Job 模式落地 Implementation Plan

> **For agentic workers:** 用 superpowers:subagent-driven-development 或 executing-plans 逐 Task 实现。Steps 用 checkbox（`- [ ]`）跟踪。

**Goal:** 新建独立模块 `rule-job-svc`，把 D11「Job 模式」从设计落为可运行实现——进程内调度器到点 → 按 `JobDefinition.subjectQuery`（首期仅 SQL）查一批主体 → 为每个主体合成标准 `RuleEvent` → 经 `EvalService.acceptEvent` 注入标准评估链路 → 记 `JobExecution`。Job 只是 Trigger 适配器，不引入第四个一等概念。

**Architecture:** 调度（`Scheduler` SPI 进程内实现）→ 取数（`SqlSubjectQueryRunner`）→ 合成注入（`JobRunner`）→ 记录（`JobExecution` 同步写）四段。`JobService` 管 CRUD + 手动触发 + 运行记录查询（D11 文档里画在 `Scheduler` 接口上的 `triggerOnce`/`status`/`recentRuns` 管理能力**上移到 service 层**，SPI 只保留 `schedule`/`unschedule`）。下游 Matcher/AST/Action 对 Job 完全无感。

**Tech Stack:** Java 25、Spring Boot 4、Spring Modulith、MyBatis-Plus、Flyway、Guava（murmur3）、JUnit5 + Mockito + Testcontainers。subjectQuery 取数统一走 MyBatis（`@Select` Mapper），不引入 JdbcTemplate。

**本机跑测试前置：** 先用 `mvn-env` skill 设 `$MVN`，再 `$MVN -pl rule-job-svc -am test`。每个 Task 提交前该模块测试全绿，不 `-DskipTests`。

## 写计划前已拍板的开放点（code-architect 摸排 + 现有契约确认）

1. **注入点 = `EvalService.acceptEvent(RuleEvent)→boolean`**（异步 PUSH 语义，session source 记 PUSH，与文档「Job 归 PUSH」一致）。不是 `evaluate`（那是同步 PULL，硬编码 source="PULL"）。`successCount` = `acceptEvent` 返回 true 的主体数（= 成功注入，不是命中）。
2. **DDL 迁移落 config-svc canonical**：`rule-config-svc/src/main/resources/db/migration/V1_7__job_tables.sql`（config-svc 是单一权威 schema 源），job-svc 测试资源复制一份。
3. **ArchUnit 加 job-svc 边界规则**（对齐 B28 意图）：job 禁碰 eval/config 的 `internal`；eval/config 禁反向依赖 job。Modulith 本仓不用 `verify()`/`package-info`/`allowedDependencies`，边界靠 ArchUnit + Maven 依赖方向 + api/internal 包约定。
4. **`job_definition` 存 `scene_code`（不是文档 DDL 的 `scene_id`）**：`SceneService` 全部按 `sceneCode` 查询、无 by-id 接口，且 `RuleEvent.sceneCode` 也是 code；存 code 则 PULL 校验与合成 RuleEvent 零转换。需同步改 `05-storage.md` DDL（`scene_id`→`scene_code`）+ `01-concepts.md §3.10` 字段表。
5. **`eventId = murmur3_128(jobRunId + ":" + subjectId)` 十六进制**：复用 Guava（kernel ROLLOUT gate 已用）。`jobRunId` = `JobExecution.id`。落 `evaluation_session(tenant_id, event_id)` uk 做幂等（`EvalSessionWriter` 已实现 DuplicateKey 兜底），Job 端无需自建幂等表。
6. **`RuleEvent` 无 `source` 字段**：不给 RuleEvent 加 source=JOB（那要改 kernel api，超范围）。Job 注入后 session source 由 `EvalServiceImpl.acceptEvent` 决定。
7. **subjectQuery JSON 形状（SQL type）**：`{"type":"SQL","sql":"SELECT user_id AS subjectId, ... FROM ..."}`。`SqlSubjectQueryRunner` 经 `SubjectQueryMapper.@Select("${sql}")` 跑配置化只读 SQL → `List<Map<String,Object>>`，每行须含 `subjectId` 列；其余列供 `payloadTemplate` 占位符填充。SQL 为运营侧可信配置，非终端用户输入。
8. **payloadTemplate**：JSON 对象，值为 `${columnName}` 占位符的用主体行同名字段替换，其余原样。
9. **JobExecution 同步写**（模块内运行记录，非跨模块），不走 Modulith 事件。
10. **JSON 字段映射**：entity 用 `private String`，service/runner 层注入全局 `ObjectMapper`（Jackson 3 `tools.jackson`）手动解析，不用 MyBatis TypeHandler。DTO↔entity 手写，不用 MapStruct。

## DDL（V1_7__job_tables.sql）

```sql
CREATE TABLE IF NOT EXISTS job_definition (
    id              BIGINT       NOT NULL AUTO_INCREMENT,
    tenant_id       VARCHAR(64)  NOT NULL,
    scene_code      VARCHAR(128) NOT NULL,
    code            VARCHAR(128) NOT NULL,
    name            VARCHAR(255) NOT NULL,
    cron_expression VARCHAR(128) NOT NULL,
    subject_query   JSON         NOT NULL,
    event_type      VARCHAR(128) NOT NULL,
    payload_template JSON        NULL,
    status          VARCHAR(16)  NOT NULL DEFAULT 'ACTIVE',  -- ACTIVE / DISABLED
    created_by      VARCHAR(64)  NULL,
    created_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_by      VARCHAR(64)  NULL,
    updated_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_tenant_scene_code (tenant_id, scene_code, code)
);

CREATE TABLE IF NOT EXISTS job_execution (
    id                BIGINT      NOT NULL AUTO_INCREMENT,
    job_definition_id BIGINT      NOT NULL,
    tenant_id         VARCHAR(64) NOT NULL,
    trigger_at        DATETIME    NOT NULL,
    status            VARCHAR(16) NOT NULL,  -- RUNNING / SUCCESS / PARTIAL_FAIL / FAILED
    subject_count     INT         NOT NULL DEFAULT 0,
    success_count     INT         NOT NULL DEFAULT 0,
    error_count       INT         NOT NULL DEFAULT 0,
    error_summary     TEXT        NULL,
    finished_at       DATETIME    NULL,
    PRIMARY KEY (id),
    KEY idx_job_trigger (job_definition_id, trigger_at)
);
```
