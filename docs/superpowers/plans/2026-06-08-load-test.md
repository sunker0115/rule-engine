# 规则引擎压测（探顶找瓶颈 · PULL · JVM）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 搭一套可复跑的压测 harness，探顶找出 PULL `/evaluate` 的业务逻辑瓶颈（连接池、session 两写、action 写、trace 开销），用数据佐证瓶颈排序。

**Architecture:** 顶层 `load-test/` 放三个物：一个 `@SpringBootTest` 程序化 seeder（经已校验的 config 写服务造 scene+metric+规则，typed 构造 + 冒烟校验）、一个 k6 脚本打 PULL `/evaluate`、一套配置臂 runbook + 观测脚本。被测是 JVM jar；seed 在 app 启动前完成（ACTIVE 规则由 `IndexStartupLoader` 启动期载入内存索引）。本计划只测现状 + 零代码配置旋钮对照，改代码的优化留二期。

**Tech Stack:** Spring Boot 4 `@SpringBootTest`(seeder) / k6(HTTP 负载) / async-profiler(flame graph) / actuator-prometheus(指标) / MySQL。规则写经 `SceneService`·`MetricWriteService`·`ConfigService`，条件 AST 为 `ConditionNode`(conditionType=`GTE`)。

---

## 关键事实（实现前必读，均经代码核实）

1. **ACTIVE 规则启动期载入索引**：`IndexStartupLoader.onApplicationReady`(`ApplicationReadyEvent`) 把所有 ACTIVE 规则灌进 `SceneRuleIndex`。**seed 必须先于被测 app 启动**（或 seed 后重启 app），否则索引为空、`match` 返回空 → 评估走 miss 路径（不落库）→ 压测无效。
2. **匹配键** = `(tenantId, sceneCode, eventType)`（`SceneRuleIndex.match`）。seed 的 scene/规则与 k6 请求的 eventType 必须一致。
3. **kind=`AST_BOOLEAN`** 走 `TracingInterpretedExecutor`（`EvalEngine` 的 kind→executor map）。
4. **条件 AST 形状**（`ConditionNode` record，`AstJsonCodec` 序列化，判别字段 `"type":"ConditionNode"`）：
   字段 `conditionType` / `metricCode` / `displayLabel` / `params` / `weight`(AST_BOOLEAN 忽略) / `dataType`。数值比较算子 key：`EQ/NEQ/GT/GTE/LT/LTE/...`（`KernelEvaluators.defaults()`）。`AbstractNumericEvaluator` 读 `ctx.getMetric(metricCode)`、`params.get("threshold")`、`dataType`。
   **全命中条件**：`demo.score GTE 0`，k6 在 providedMetrics 传 `demo.score=100`（100≥0 恒命中）。
5. **写服务签名**（rule-config-svc，`com.sstlfsj.rule.config.api.service`）：
   - `SceneService.createScene(tenantId, sceneCode, name, description, dominantMode, subjectType, eventTypesJson, payloadSchemaJson, defaultParamsJson, actorId) → Long`
   - `MetricWriteService.create(Long tenantId, String metricCode, MetricWriteCommand cmd, actorId) → Long`；`MetricWriteCommand(name, sourceType, dataType, Map<String,Object> params, Integer cacheTtlSeconds, boolean allowProvided)`
   - `ConfigService.createDraft(tenantId, sceneCode, code, name, conditionAstJson, decisionBindingsJson, preGatesJson, triggerEventTypesJson, kind, actorId) → DraftCreatedResult`
   - `ConfigService.publish(tenantId, ruleDefinitionId, actorId) → RuleVersionSnapshot`
6. **providedMetrics 不取数**：`EvalContextAssembler` 在 metric 已 provided 时直接用提供值，不走 SQL/HTTP（metric `allowProvided=true`）。
7. **PULL 契约**（`EvalController` + `EvalEventRequest`）：`POST /api/v1/rule/evaluate`，body `{tenantId, sceneCode, eventType, subjectId, eventId, occurredAt, payload, providedMetrics}`。**eventId 每请求唯一**（否则撞 `uk_tenant_event` 走幂等去重，偏离写路径测量）。

**需在 spike(Task 1) 确认（未核实，不要当已知）**：(a) `decisionBindings` 引用的 decisionCode 是否需 decision_definition 预存才能 publish；(b) `scene_action_binding` 的写入路径（MetadataService 只读，未见写服务）——决定 action_execution 写是否可测；(c) `DraftCreatedResult` 取 ruleDefinitionId 的字段/方法名。

```java
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;

import java.util.Map;

/** 压测数据播种器（手动触发）：经已校验写服务造 scene+metric+规则。 */
@SpringBootTest
@Tag("loadtest")
class LoadTestSeeder {

    static final String TENANT = "9001";          // 专用压测租户，清理按此 DELETE
    static final String SCENE = "loadtest";
    static final String EVENT_TYPE = "login";
    static final String METRIC = "demo.score";
    static final String ACTOR = "loadtest";

    @Autowired SceneService sceneService;
    @Autowired MetricWriteService metricWriteService;
    @Autowired ConfigService configService;

    /** AST：demo.score GTE 0（provided 100 恒命中）。 */
    static String conditionAstJson() {
        return "{\"type\":\"ConditionNode\",\"conditionType\":\"GTE\","
             + "\"metricCode\":\"" + METRIC + "\",\"displayLabel\":\"score>=0\","
             + "\"params\":{\"threshold\":0},\"dataType\":\"LONG\"}";
    }

    @Test
    void seedMinimalAndVerify() {
        sceneService.createScene(TENANT, SCENE, "Load Test Scene", null,
                "HYBRID", "USER", "[\"" + EVENT_TYPE + "\"]", null, null, ACTOR);
        metricWriteService.create(Long.valueOf(TENANT), METRIC,
                new MetricWriteCommand("demo score", "SQL_AGGREGATE", "LONG", Map.of(), null, true),
                ACTOR);
        DraftCreatedResult draft = configService.createDraft(TENANT, SCENE,
                "lt-rule-1", "lt rule 1",
                conditionAstJson(), "[{\"decisionCode\":\"PASS\"}]",
                "[]", "[\"" + EVENT_TYPE + "\"]", "AST_BOOLEAN", ACTOR);
        configService.publish(TENANT, draft.ruleDefinitionId(), ACTOR);
    }
}
```

```java
    /** 按租户清理压测数据，可重跑（不 TRUNCATE 共享表）。注入 config-svc 写/删路径或直连 mapper 按 tenant_id=9001 DELETE。 */

        // 用 Task 1 确认的 mapper/服务按 TENANT 删除：rule_version→rule_definition→scene_*→metric_definition→scene
        // 顺序遵守外键依赖；具体 mapper 见 rule-config-svc internal（与 createScene/createDraft 同源）
    }

    /** 生成 ruleCount 条全命中规则（code 唯一、条件同形、均 publish 为 ACTIVE）。 */
    void seedRules(int ruleCount) {
        sceneService.createScene(TENANT, SCENE, "Load Test Scene", null,
                "HYBRID", "USER", "[\"" + EVENT_TYPE + "\"]", null, null, ACTOR);
        metricWriteService.create(Long.valueOf(TENANT), METRIC,
                new MetricWriteCommand("demo score", "SQL_AGGREGATE", "LONG", Map.of(), null, true), ACTOR);
        for (int i = 1; i <= ruleCount; i++) {
            DraftCreatedResult draft = configService.createDraft(TENANT, SCENE,
                    "lt-rule-" + i, "lt rule " + i,
                    conditionAstJson(), "[{\"decisionCode\":\"PASS\"}]",
                    "[]", "[\"" + EVENT_TYPE + "\"]", "AST_BOOLEAN", ACTOR);
            configService.publish(TENANT, draft.ruleDefinitionId(), ACTOR);
        }
    }
```

`load-test/k6/evaluate.js`：

```javascript
import http from 'k6/http';
import { check } from 'k6';
import { Counter } from 'k6/metrics';

const BASE = __ENV.BASE_URL || 'http://localhost:8080';
const hits = new Counter('rule_hits');

// 阶梯加压：每档 30s 平台，逐级抬高 VU，观察拐点
export const options = {
  scenarios: {
    ramp: {
      executor: 'ramping-vus',
      startVUs: 10,
      stages: [
        { duration: '30s', target: 25 },
        { duration: '30s', target: 50 },
        { duration: '30s', target: 100 },
        { duration: '30s', target: 200 },
        { duration: '30s', target: 400 },
      ],
      gracefulRampDown: '5s',
    },
  },
  thresholds: {
    http_req_failed: ['rate<0.01'],
    http_req_duration: ['p(95)<200', 'p(99)<500'],  // 仅作报警线，探顶不强制
  },
};

export default function () {
  const url = `${BASE}/api/v1/rule/evaluate`;
  // eventId 每次唯一 → 走真实写路径，不触发幂等去重
  const eventId = `${__VU}-${__ITER}-${Date.now()}`;
  const body = JSON.stringify({
    tenantId: '9001',
    sceneCode: 'loadtest',
    eventType: 'login',
    subjectId: `s-${__VU}`,
    eventId: eventId,
    payload: {},
    providedMetrics: { 'demo.score': 100 },
  });
  const res = http.post(url, body, { headers: { 'Content-Type': 'application/json' } });
  const ok = check(res, {
    'status 200': (r) => r.status === 200,
    'ruleHit true': (r) => r.json('data.ruleHit') === true,
  });
  if (ok) hits.add(1);
}
```

```bash
#!/usr/bin/env bash
# 抓一帧关键指标（高 VU 平台期跑）。用法：./capture-prometheus.sh [baseUrl]
set -euo pipefail
BASE="${1:-http://localhost:8080}"
TS=$(date +%H%M%S)
curl -s "${BASE}/actuator/prometheus" | grep -E \
  'hikaricp_connections_active|hikaricp_connections_pending|hikaricp_connections_idle|jvm_gc_pause|http_server_requests_seconds_count|executor_active|executor_queued' \
  | grep -v '#' | sort > "/tmp/loadtest-metrics-${TS}.txt"
echo "saved /tmp/loadtest-metrics-${TS}.txt"
grep -E 'hikaricp_connections_(active|pending)' "/tmp/loadtest-metrics-${TS}.txt" || true
```
